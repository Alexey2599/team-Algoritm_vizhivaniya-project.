## 5. Практическая работа с Git

Каждый участник выполнил следующую последовательность (пример для Гапонова Романа):

```bash
git clone https://github.com/[логин_создателя]/team-[название_команды]-project.git
cd team-[название_команды]-project
git checkout -b feature/gaponov
# вносим изменения: дополняем отчёт/документы по своей роли
git add docs/roles-and-responsibilities.md
git commit -m "feat: добавил описание трудовых функций для роли [роль]"
git push origin feature/gaponov
```

Затем на GitHub создан Pull Request `feature/gaponov → main`, получено ревью другого участника, выполнено слияние (merge).

## 6. Вывод

Система контроля версий превращает репозиторий в единое рабочее пространство команды. Каждый коммит фиксирует автора, время и суть изменения, поэтому по истории (`git log`, вкладка Commits) можно определить вклад каждого участника. Ветки позволяют работать параллельно, не мешая друг другу, а Pull Request добавляет этап проверки: изменения попадают в `main` только после ревью, что напрямую связано с распределением ролей R и A — исполнитель вносит изменения, ответственный за результат принимает их. Единая структура папок упрощает проверку работ преподавателем.

## Ответы на контрольные вопросы

1. **Репозиторий** — хранилище проекта: файлы, папки и история изменений. Нужен для хранения и совместной работы.
2. **Преимущества Git:** история изменений, параллельная работа через ветки, возможность откатиться, видимый вклад каждого.
3. **Коммит** — зафиксированный снимок изменений. Сообщение должно кратко и понятно описывать суть изменения (не «fix» или «update», а, например, «Добавлена валидация формы регистрации»).
4. **Ветка и main:** ветка — отдельная линия разработки для задачи; main — стабильная основная версия проекта, в которую ветки вливаются после проверки.
5. **Pull Request** — запрос на слияние ветки в другую. Связан с ответственностью: исполнитель (R) предлагает изменения, ответственный (A) проверяет и принимает.
6. **Вклад участников** определяется по истории коммитов: автор, дата, содержание, количество изменений.
7. **Регистрация на GitHub** нужна для идентификации автора, доступа к репозиторию и права вносить изменения.
